### P2 — behavior / design (decide, then apply)

- **#4 — `internal/cli/slackcookie_accounts.go:66` — per-account DB filename collisions merge two
  workspaces' mirrors (breaks KTD2 isolation).** `sanitizeAccountFilename` maps every non
  `[A-Za-z0-9_-]` rune to `_`, so `team.a` and `team_a` both resolve to `team_a.db` and their
  mirrors silently merge — a cross-workspace data/privacy leak. *Fix:* reject `SaveAccount` when the
  sanitized name collides with a different existing account, or disambiguate with a short hash suffix
  (`<safe>-<sha8>.db`). Decision: reject-on-collision vs hash-suffix.
- **#6 — `internal/cli/missed.go:35` — `missed --all-accounts` matches mentions with one account's
  user id across every workspace.** Separate logins have different user ids; the single resolved id
  is applied to all mirrors, so non-active-account mentions never match (DMs still surface). *Fix:*
  resolve the user id per account inside the mirror loop (needs a per-account-id design), or document
  that `--all-accounts` mention matching only covers the active account.
- **#8 — `internal/cli/slacksql.go:24` — `sql` keyword denylist rejects valid read-only SELECTs**
  whose text contains write keywords (e.g. `WHERE data LIKE '%update%'`). Real read-only safety is
  already the DSN `mode=ro` open + single-statement + SELECT/WITH-prefix checks. *Fix (security
  tradeoff to confirm):* keep ATTACH/DETACH/PRAGMA rejection, drop (or only match outside string
  literals) the DML keyword block, relying on `mode=ro`.
- **#11 — `internal/cli/stale_threads.go:34` — `stale-threads` without `--me` returns ALL threads.**
  Unlike `missed`, it never calls `resolveMyUserID`, so the participation filter never fires. *Fix:*
  call `resolveMyUserID(ctx, flags, me)` like `missed` does (changes the default behavior — confirm
  that is desired), or add `me_resolved:bool` to the JSON so an agent knows to re-call with `--me`.
- **#12 — `internal/cli/stale_threads.go:62` — loads entire message history (zero `--since` bound).**
  It needs old rows by design (stale = no recent reply), so it cannot simply filter `since=cutoff`.
  *Fix:* add an implicit look-back floor (e.g. inactivity > 180d cannot be newly stale) or a
  `--max-history` flag (default ~90d) and pass it as the `since` bound. Decision: the floor value.

### P2 — reliability / performance (mechanical, but held for review)

- **#3 — `internal/cli/ai.go:184` — `ai recap` discards the `Ask` error**, so Ctrl-C / deadline
  mid-poll prints "No recap available" instead of propagating cancellation. *Fix:*
  `ask, askErr := ai.Ask(...)`; then `if askErr != nil && cmd.Context().Err() != nil { return cmd.Context().Err() }`.
- **#7 — `internal/cli/slackcookie_offline.go:100` — `loadMessages` loads every message row and uses
  the context-unaware `Store.Query`** (filters `--since` in Go). Touches the shared offline hot path.
  *Fix:* add `Store.QueryContext` (honor cancellation); when `since` is non-zero, append `AND id >= ?`
  bound to `strconv.FormatInt(since.Unix(),10)+".000000"` (the `id` column holds the sortable `ts`),
  keeping the in-Go time check as a sub-second safety net. Apply only where `since` is a real cutoff
  (not stale-threads, which passes zero — see #12).
- **#10 — `internal/cli/slacksql.go:112` — `sql` materializes the full result set with no row/size
  cap** (local OOM via a recursive CTE / `SELECT *` over a large mirror). *Fix:* stop with a warning
  after a max row count (e.g. 100k) and/or inject a default `LIMIT`; cap per-cell size in
  `normalizeSQLValue`.

## Residual risks (note; mostly defense-in-depth / live-verify)

- **Security (plan-acknowledged):** `client.maskCredentialText` (`internal/client/client.go:957`, a
  **generated** file) masks the xoxc token but not the `d`/`d-s` cookie. No confirmed sink today
  (dry-run omits headers; error bodies don't echo the request cookie). Fix touches a generated file →
  record under `.printing-press-patches/`. The plan already lists "extend maskCredentialText to cover
  the cookie" as a mitigation.
- `SLACK_COOKIE_BASE_URL` (config.go) sets `BaseURL` with no https upgrade (same root cause as #1).
- `config.persisted()` serializes `cfg.Headers` incl. the injected `Cookie`; safe only because no
  wired command saves the post-`ApplyAccount` transient cfg. A future save would write the cookie to
  `config.toml` in cleartext. Invariant documented (`slackcookie_config.go:178`) but unenforced.
- `ai ask` settle heuristic could return a constant "thinking…" placeholder as the answer if held ≥2
  poll intervals; `filterReplies` returns any non-question thread message as the "answer". Verify
  against live streaming shape during U15.
- `ai recap --dry-run` gates the `ai.Ask` post but still fires `ai.DigestChannels` (a POST to an
  undocumented endpoint), so `--dry-run` is not fully honored.
- `ExtractXoxcToken` returns the first `xoxc-` match; a multi-team boot blob could yield a non-active
  token (Slack-controlled over https, low risk).
- Six hand-authored `internal/cli` files (`ai.go`, `digest.go`, `missed.go`, `trends.go`,
  `slacksql.go`, `stale_threads.go`) lack the `slackcookie_` prefix of the other siblings and are not
  listed in `.printing-press-patches`; if a future `generate --force` ever emits same-named files
  they could collide. Named intentionally in the plan's Output Structure, but durability uncaptured.
