Slack mirror — domain glossary

A local account mirror holds observations from one verified Slack workspace. Its purpose is to support correctly scoped reads of accessible conversations and messages.

Account
A named Slack login selected by the user. Avoid: Workspace identity, tenant ID.
Observing workspace
The Slack workspace through which a message was observed. Avoid: Author's team, account alias, workspace slug.
Conversation
A public channel, private channel, direct message, or group direct message. Avoid: Channel when the meaning excludes direct messages.
Message
A Slack message identified within its observing workspace and conversation by its exact timestamp. Avoid: Timestamp as globally unique message ID.
Thread
A conversation's root message and the replies associated with that root. Avoid: Thread timestamp as globally unique thread ID.
Observation
A copy of a message received from a particular Slack source. Multiple observations can describe the same message. Avoid: Duplicate message, independent history message.
Tombstone
A retained record of an explicitly observed message deletion. Avoid: Message missing from history.
Coverage
The extent to which relevant accessible source data has been enumerated for a stated scope. Avoid: Freshness, deletion coverage, entire workspace completeness.
Legacy row
An existing mirror record whose observing-workspace or conversation identity cannot be verified. Avoid: Inferred channel, safely attributed message.

Consequential decision records

0001 — Preserve ambiguous legacy records

The old timestamp-only mirror cannot prove conversation attribution. Preserve it behind a verified consistent backup and quarantine unverified rows, then require source re-fetch for canonical attribution. This costs storage and an explicit recovery step, but avoids silently inventing identity or destroying recoverable evidence.

0002 — Canonical current state with explicit tombstones

History, replies and search describe overlapping messages and can replay stale copies. Keep one current message per verified workspace/conversation/timestamp, with revision and observation provenance, and retain explicit deletion tombstones. A full revision archive is outside phase 1; absence from history remains insufficient deletion evidence.

0003 — Discover roots outside the selected reply window

A new reply can belong to an old retained root. Complete window coverage therefore requires retained-root discovery outside that window before collecting replies. Partial discovery is resumable and explicitly partial; operation budgets and pacing belong to phase 2.
